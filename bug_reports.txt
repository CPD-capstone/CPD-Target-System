Bug Reports
===========

Status note: The following defects were found during the UI test pass and have
been fixed. Their reproduction steps describe the behavior before the fixes.

BUG-001 - Drill blocks cannot be dragged in the local preview

When opening the Drills page through the local preview server, the compressed-only
SortableJS asset returns 404 instead of loading the drag-and-drop library.

Steps to reproduce:
1. Start the local preview server from the repository's data directory.
2. Open http://127.0.0.1:8768/drills.html?test=1.
3. Open or create a drill and try to drag a sequence block into the drill.
4. Observe that dragging does not work and the browser reports a missing SortableJS asset.

Expected: SortableJS loads, allowing drill blocks to be dragged and reordered.
Observed: The server could not serve the vendored .gz-only asset, so the drag-and-drop
library did not load.
Fix/verification: The preview server now falls back to compressed assets and sends
the gzip content-encoding and JavaScript MIME headers. Drag-and-drop was verified
in the browser.

BUG-002 - Performance PDF export fails to create a PDF

When exporting a Performance PDF with stale or incorrectly typed cached module assets,
the export displays "Could not create the PDF. Check the controller connection and
try again." instead of generating the PDF.

Steps to reproduce:
1. Start the local preview server and open http://127.0.0.1:8768/Performance.html?test=1.
2. Load or enter a qualification score in test mode.
3. Select Export PDF.
4. Observe the PDF error message rather than a generated PDF.

Expected: The qualification report is generated as an application/pdf document.
Observed: The PDF module failed to load from the cached asset response, and export
showed the generic creation error.
Fix/verification: JavaScript asset serving and the PDF module cache-busting version
were corrected. PDF generation was verified, producing an application/pdf blob.
